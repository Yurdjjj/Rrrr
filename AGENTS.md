# 🤖 AGENTS.MD — Инструкции для AI-агентов и ассистентов разработки

Этот файл содержит ключевые архитектурные правила, стек технологий, соглашения по коду и бизнес-требования для AI-агентов (Antigravity, Cursor, Claude Code, Copilot и др.), работающих над проектом **AI TestPlatform**.

---

## 🎯 1. Контекст и бизнес-цель проекта

Платформа представляет собой двустороннюю EdTech-систему:
1. **Преподаватель (Teacher)**: создает тесты с помощью генеративных ИИ-моделей (на основе тем, текстов, файлов), редактирует их, публикует и анализирует результаты.
2. **Ученик (Student)**: проходит тесты в чистом, удобном и защищенном интерфейсе, получает мгновенные оценки и разбор ошибок.

Все предлагаемые вами архитектурные решения и код должны учитывать специфику образования: надежность, интуитивность интерфейса, защита от списывания и безопасность персональных данных учеников.

---

## 🏛 2. Архитектурные принципы и безопасность

### 🚨 Критическое правило безопасности (Тестирование)
- **НИКОГДА** не отправлять на клиент (ученику) правильные ответы (`correct_answers`), объяснения (`explanations`) или критерии оценки во время прохождения теста.
- Схема вопроса для клиента: `id`, `question_text`, `type`, `options: [{ id, text }]` (без флага `is_correct`).
- Проверка ответов должна производиться **исключительно на сервере** после отправки формы учеником (или по завершении таймера).
- После завершения теста сервер возвращает объект результата: набранные баллы, разбор ошибок и пояснения.

### 👥 Ролевая модель (RBAC)
- Четкое разделение ролей: `TEACHER`, `STUDENT`, `ADMIN`.
- Учитель имеет доступ на чтение/запись только к своим тестам и результатам своих групп/учеников.
- Ученик не должен иметь доступа к эндпоинтам редактирования тестов или просмотра чужих результатов.

## 🧠 3. Правила работы с LLM и генерацией контента

1. **Строго структурированный вывод (Structured Outputs)**:
   - Все запросы к LLM (Gemini, OpenAI и др.) для генерации тестов должны требовать строгий JSON с валидацией схемы (через Pydantic в Python или Zod в TypeScript).
   - Никогда не парсить неструктурированный текст регулярными выражениями, если доступен JSON Mode / Structured Output.

2. **Схема вопроса по умолчанию**:
   ```json
   {
     "question": "Текст вопроса",
     "type": "single_choice | multiple_choice | text_input | matching",
     "options": [
       {"id": "a", "text": "Вариант 1"},
       {"id": "b", "text": "Вариант 2"}
     ],
     "correct_answer": ["a"],
     "explanation": "Подробное объяснение, почему данный ответ правильный",
     "points": 1,
     "difficulty": "easy | medium | hard"
   }
   ```

3. **Защита от галлюцинаций и валидация**:
   - Автоматически проверять, что `correct_answer` действительно присутствует в списке `options`.
   - В тестах типа `single_choice` массив правильных ответов обязан содержать ровно 1 элемент.
   - Реализовать механизм повторных попыток (retries) при получении невалидного JSON от LLM.

4. **Оценка открытых ответов (Free-form / Open-ended)**:
   - При оценке развернутых текстовых ответов передавать модели четкий рубрикатор и эталонный ответ.
   - Модель должна возвращать: `score` (от 0 до max), `feedback` (что сделано хорошо, где неточность).

## 💻 4. Стандарты написания кода

- **Типизация**: 
  - Полная статическая типизация (TypeScript `strict: true` на фронтенде/бэкенде Node.js; строгие type hints и Pydantic на Python).
  - Избегать типов `any`.
- **Обработка ошибок**:
  - Все сетевые вызовы и обращения к LLM API должны быть обернуты в `try/catch` с информативными сообщениями об ошибках и fallbacks.
  - Учитывать rate limits от провайдеров LLM (статус 429) и реализовывать exponential backoff.
- **Чистота кода**:
  - Придерживаться принципов SOLID и DRY.
  - Разделять бизнес-логику, доступ к данным (DAL/ORM) и контроллеры/роутеры.

---

## 🎨 5. Гайдлайны по UI/UX

- **Для ученика (Mobile-first & Accessible)**:
  - Минималистичный интерфейс, фокус на вопросе, отсутствие визуального шума.
  - Крупные, удобные кнопки вариантов ответа для тачскринов.
  - Заметный, но не раздражающий таймер.
  - Предупреждение перед отправкой, если остались неотвеченные вопросы.
- **Для учителя**:
  - Интерактивный предпросмотр теста в реальном времени ("Как увидит ученик").
  - Удобный редактор: возможность в один клик перегенерировать отдельный вопрос, который не понравился.
  - Наглядные графики и диаграммы успеваемости (гистограммы распределения баллов).
