# Пользовательские истории (User Stories, 5-сабақ)

Формат истории: **«Как [роль], я хочу [действие], чтобы [польза]»**  
Приоритеты MoSCoW:
- **M (Must have)** — обязательно для MVP (строго 3–4 истории).
- **S (Should have)** — важно, но можно отложить до следующей итерации.
- **C (Could have)** — желательно, если останется время.
- **W (Won't have)** — не входит в текущую версию проекта.

---

## Реестр историй

| ID | Роль и история | Приоритет | Проверяемый критерий приёмки (Acceptance Criteria) |
| :--- | :--- | :---: | :--- |
| **US-1** | **Как преподаватель**, я хочу создать новый тест с названием и темой, **чтобы** организовать проверочную работу к уроку. | **M** | Название содержит от 3 до 200 символов (иначе `422 Unprocessable Entity`). Созданный тест сохраняется в статусе «не опубликован», автор — текущий преподаватель. |
| **US-2** | **Как преподаватель**, я хочу сгенерировать 3–5 тестовых вопросов по тексту лекции с помощью ИИ, **чтобы** не тратить часы на ручной подбор вариантов. | **M** | На вход передается текст от 50 до 10 000 символов. ИИ возвращает вопросы с 2–5 вариантами ответа и указанием правильного. При сбое внешнего сервиса ИИ возвращается ошибка с сохранением возможности ручного ввода. |
| **US-3** | **Как преподаватель**, я хочу опубликовать готовый тест, **чтобы** сделать его доступным для прохождения студентами. | **M** | Тест без добавленных вопросов не может быть опубликован (ошибка `400 Bad Request`). После публикации тест получает уникальный идентификатор и статус `is_published = True`. |
| **US-4** | **Как студент**, я хочу отправить свои ответы на опубликованный тест, **чтобы** мгновенно узнать набранный балл. | **M** | Тест должен быть опубликован (иначе `403 Forbidden`). Правильные ответы не передаются на клиент во время прохождения. Количество ответов должно строго совпадать с количеством вопросов (иначе `400 Bad Request`). Ответ содержит итоговый балл. |
| **US-5** | **Как студент**, я хочу увидеть подробный разбор ошибок и пояснения к правильным ответам после сдачи, **чтобы** понять свои пробелы в знаниях. | **S** | Пояснения к вопросам и правильные варианты возвращаются только в объекте завершенной попытки; неверно отвеченные вопросы визуально выделены. |
| **US-6** | **Как преподаватель**, я хочу просматривать список попыток и баллы студентов по моему тесту, **чтобы** оценить успеваемость группы. | **S** | Доступ к списку результатов есть только у преподавателя-автора теста (иначе `403 Forbidden`). Список содержит дату попытки, идентификатор студента и балл. |
| **US-7** | **Как преподаватель**, я хочу экспортировать результаты теста в CSV-файл, **чтобы** быстро перенести оценки в ведомость. | **C** | Формируется файл в кодировке UTF-8 со столбцами: дата, студент, набранный балл, процент правильных ответов. |
| **US-8** | **Как преподаватель**, я хочу автоматически выгружать оценки в электронный журнал (Күнделік / Platonus), **чтобы** не вбивать их дважды. | **W** | В рамках учебного MVP не реализуется. Запланировано в бэклоге интеграций на будущее. |

---

## 🎯 Граница MVP (MVP Scope)
**В MVP входят строго истории со статусом Must:** `US-1`, `US-2`, `US-3`, `US-4`.  
Это позволяет преподавателю создать тест с помощью ИИ, опубликовать его, а студенту — пройти тестирование и получить расчет баллов.
